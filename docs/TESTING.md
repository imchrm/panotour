# Тестирование полного цикла: tiler → editor → export → viewer

> Пошаговая инструкция для ручного QA всего pipeline.
> Выполняй шаги последовательно; каждый раздел содержит чеклист результата.

---

## Требования

| Инструмент | Версия | Проверка |
|---|---|---|
| Node.js | 20+ | `node --version` |
| npm | 9+ | `npm --version` |
| Браузер | Chrome/Edge (для экспорта в папку) или Firefox (только ZIP) | |
| Тестовая панорама | equirectangular JPEG/PNG, рекомендуется 4096×2048 или 8192×4096 | |

**Клонировать репозиторий и установить зависимости:**
```bash
git clone <repo-url> panotour
cd panotour
npm install
```

## Шаг 1 — Tiler: нарезка панорамы в тайлы

### 1.1 Подготовка

Положи тестовые equirectangular-панорамы (минимум 2, для проверки навигации между сценами):

```
panotour/
  panos/
    entrance.jpg   # 4096×2048 или больше
    hall.jpg
```

### 1.2 Запуск tiler (только desktop)

```bash
# Сцена 1
node packages/tiler/tiler.js \
  --input ./panos/entrance.jpg \
  --output ./packages/viewer/tiles/scene-01 \
  --id scene-01

# Сцена 2
node packages/tiler/tiler.js \
  --input ./panos/hall.jpg \
  --output ./packages/viewer/tiles/scene-02 \
  --id scene-02
```

### 1.3 Запуск tiler с мобильными тайлами (флаг `--mobile`)

```bash
node packages/tiler/tiler.js \
  --input ./panos/entrance.jpg \
  --output ./packages/viewer/tiles/scene-01 \
  --id scene-01 \
  --mobile
```

### 1.4 Чеклист: ожидаемая структура файлов

После выполнения без `--mobile`:
```
packages/viewer/tiles/scene-01/
  preview.jpg          # 256×256 px, должен быть читаемым (front face)
  manifest.json        # JSON с массивом levels[]
  1/                   # уровни тайлов
    f/
      y/
        x.jpg
```

После выполнения с `--mobile`:
```
packages/viewer/tiles/scene-01/
  preview.jpg
  manifest.json
  1/ ...               # desktop-тайлы
  mobile/
    preview.jpg
    manifest.json
    1/ ...             # mobile-тайлы (tileSize=256)
```

**Проверить `manifest.json`:**
```bash
cat packages/viewer/tiles/scene-01/manifest.json
```
Ожидаемый формат:
```json
{
  "id": "scene-01",
  "levels": [
    { "tileSize": 256, "size": 256, "fallbackOnly": true },
    { "tileSize": 512, "size": 512 },
    { "tileSize": 512, "size": 1024 }
  ]
}
```
Количество уровней зависит от ширины входного изображения (4096 → 3 уровня, 8192 → 4 уровня).

## Шаг 2 — Editor: расстановка хотспотов

### 2.1 Запуск редактора

```bash
npm run editor
# → http://localhost:5173
```

### 2.2 Загрузка сцен

1. Открыть `http://localhost:5173` в браузере.
2. Нажать **+ Add scene** (или кликнуть область загрузки файлов).
3. Выбрать оба файла `entrance.jpg` и `hall.jpg`.
4. Убедиться, что обе сцены появились в левой колонке (`PanoramaList`).
5. Кликнуть на первую сцену — панорама должна отрисоваться в центральной области через Marzipano.

**Ожидаемый результат:** сфера с панорамой рендерится, можно перетаскивать мышью.

### 2.3 Настройка сцен

Для каждой сцены (правая колонка, `SceneSettings`):
- [ ] Ввести понятное название (например, «Вход», «Холл»)
- [ ] Подкорректировать `initialView` если нужно (yaw/pitch/fov в радианах, по умолчанию 0/0/1.5708)

Назначить сцену по умолчанию:
- [ ] В `PanoramaList` нажать ☆ рядом с первой сценой → иконка должна стать ★

### 2.4 Добавление навигационного хотспота (link)

1. Убедиться, что активна **сцена 1** (entrance).
2. В правой колонке нажать **+ Nav** — вверху canvas появится баннер `Click to place · Esc to cancel`.
3. Кликнуть по панораме в направлении «выхода в холл» — хотспот появится в списке.
4. Заполнить форму хотспота:
   - `Target scene` → выбрать «Холл»
   - `Target yaw` / `Target pitch` — направление взгляда при входе в новую сцену (радианы)
   - `Target fov` — оставить 1.5708 (90°)
5. Повторить для **сцены 2**: добавить nav-хотспот обратно в «Вход».

**Ожидаемый результат:** в списке хотспотов каждой сцены по 1 записи типа `link`.

### 2.5 Добавление информационного хотспота (info)

1. Переключиться на **сцену 1**.
2. Нажать **+ Info**.
3. Кликнуть по интересному объекту на панораме.
4. Заполнить форму:
   - `Title` — название объекта
   - `Text` — описание (поддерживается HTML)
   - `Image URL` — опционально, например `media/photo.jpg` (относительный путь)
   - `Video URL` — опционально, YouTube embed-ссылка вида `https://www.youtube.com/embed/VIDEOID`

**Ожидаемый результат:** в списке хотспотов 2 записи: 1 × link + 1 × info.

## Шаг 3 — Export: скачивание тура

### Вариант A — Экспорт в ZIP (все браузеры)

1. Нажать кнопку **↓ ZIP** в шапке редактора.
2. Кнопка меняется на «…» на время упаковки, затем браузер скачивает `tour.zip`.
3. Распаковать архив в отдельную папку, например `~/test-tour/`.

**Ожидаемое содержимое архива:**
```
tour.zip/
  tour.json
  index.html
  app.js
  style.css
  marzipano.js
  hotspots/
    NavHotspot.js
    InfoHotspot.js
    InfoPanel.js
  transitions/
    TransitionEngine.js
    easing.js
```

### Вариант B — Экспорт в папку (Chrome/Edge)

1. Нажать кнопку **→ Folder**.
2. В диалоге выбрать или создать папку `~/test-tour/`.
3. Разрешить доступ к папке.
4. Файлы записываются напрямую без диалога скачивания.

> В Firefox кнопка **→ Folder** автоматически делает то же, что **↓ ZIP**.

### 3.1 Добавить тайлы в папку тура

Тайлы в ZIP **не включаются** (они могут занимать сотни MB).
Скопировать тайлы вручную:

```bash
cp -r packages/viewer/tiles ~/test-tour/tiles
```

### 3.2 Проверить `tour.json`

```bash
cat ~/test-tour/tour.json | python3 -m json.tool | head -40
```

Убедиться:
- [ ] Поле `version` присутствует
- [ ] `defaultSceneId` указывает на реальный id сцены
- [ ] Каждая сцена имеет `tilesPath` вида `"tiles/scene-01"`
- [ ] Хотспоты присутствуют с корректными `yaw`/`pitch` в радианах
- [ ] Нет поля `panoramaObjectUrl` (должно быть снято при экспорте)

## Шаг 4 — Viewer: запуск и проверка

### 4.1 Запуск локального сервера

```bash
npx serve ~/test-tour
# → http://localhost:3000
```

> Открывать через HTTP-сервер обязательно — `file://` не поддерживает ES modules и fetch.

Альтернативно, если тайлы остались в `packages/viewer/`:
```bash
npx serve packages/viewer
```

### 4.2 Базовая проверка (Фаза 1)

Открыть `http://localhost:3000` в браузере.

- [ ] Стартовая сцена загрузилась, панорама рендерится без артефактов
- [ ] Можно вращать взгляд мышью (drag)
- [ ] Видны навигационные хотспоты (белые круги с пульсацией)
- [ ] Виден информационный хотспот (синий круг с «i»)
- [ ] В консоли браузера нет ошибок (`F12` → Console)

### 4.3 Проверка переходов (Фаза 2 — TransitionEngine)

Кликнуть по навигационному хотспоту.

- [ ] **Zoom-in:** камера плавно приближается к хотспоту (~600 мс)
- [ ] **Fade:** плавный переход crossfade в новую сцену (~400 мс)
- [ ] **Zoom-out (land):** камера разворачивается к `targetYaw/targetPitch` в новой сцене (~500 мс)
- [ ] После завершения перехода хотспоты новой сцены активны и кликабельны
- [ ] Быстрые повторные клики не ломают анимацию (флаг `_busy` блокирует)

Перейти обратно в первую сцену:
- [ ] Навигация работает в обе стороны

### 4.4 Проверка InfoPanel (Фаза 3)

Кликнуть по информационному хотспоту.

- [ ] Панель открылась поверх viewer
- [ ] Отображается заголовок, текст, изображение (если заполнено)
- [ ] Если указан YouTube URL — iframe загружается и воспроизводится
- [ ] Если указан URL локального видео — `<video>` элемент работает

Закрытие панели:
- [ ] Кнопка **×** закрывает панель
- [ ] Клавиша **Escape** закрывает панель
- [ ] Клик по затемнённому фону (вне панели) закрывает панель
- [ ] При закрытии видео/аудио останавливается

### 4.5 Проверка мобильных тайлов (если генерировались с `--mobile`)

Открыть DevTools → вкладка **Network** → найти запросы к `tiles/scene-01/...`.

**На десктопе:** запросы идут к `tiles/scene-01/{z}/{f}/{y}/{x}.jpg`

Эмуляция мобильного устройства:
1. `F12` → иконка телефона (Toggle device toolbar)
2. Выбрать любой мобильный пресет (iPhone, Pixel и т.д.)
3. Обновить страницу (`F5`)

**На мобильном:** запросы должны идти к `tiles/scene-01/mobile/{z}/{f}/{y}/{x}.jpg`

- [ ] В консоли нет 404 на тайлы
- [ ] Панорама рендерится корректно

Проверить graceful fallback: переименовать `tiles/scene-01/mobile/` → `tiles/scene-01/mobile_bak/` и перезагрузить.
- [ ] Viewer переключается на desktop-тайлы без ошибки

## Шаг 5 — Дополнительные проверки

### tour.json в viewer

viewer читает `tour.json` из своей директории. Убедиться, что в `~/test-tour/` лежит
именно экспортированный файл, а не placeholder из `packages/viewer/tour.json`.

### Проверка нескольких сцен

- [ ] Все сцены из редактора присутствуют в туре
- [ ] Навигация образует граф без тупиков (каждая сцена доступна)

### Проверка в Firefox

- [ ] Viewer работает корректно
- [ ] Кнопка **→ Folder** в редакторе автоматически скачивает ZIP (fallback)

### Проверка `↓ tour.json`

Кнопка **↓ tour.json** скачивает только файл данных (без viewer-файлов).
Полезно для обновления тура без переупаковки всего ZIP.

- [ ] Файл скачивается, JSON валидный
- [ ] Заменить `tour.json` в `~/test-tour/`, обновить страницу viewer — изменения применились

## Типичные проблемы

| Симптом | Причина | Решение |
|---|---|---|
| Viewer: белый экран | Открыт через `file://` | Запустить HTTP-сервер |
| 404 на тайлы | `tilesPath` в tour.json не совпадает с реальным путём | Проверить `tour.json`, убедиться что `tiles/` скопированы |
| Панорама пикселизированная | Используется только fallback-уровень | Tiler вернул только 1 уровень → входное изображение < 512px |
| Хотспоты не видны | Ошибка JS в консоли | Открыть DevTools, устранить ошибку |
| Переход срабатывает один раз | `_busy` не сбрасывается | Убедиться что `LAND_DURATION` совпадает с реальной длительностью анимации |
| InfoPanel не закрывается по Escape | Фокус на другом элементе | Кликнуть по viewer, затем нажать Escape |
| ZIP не содержит viewer-файлов | Vite-сервер не запущен при экспорте | Убедиться что редактор запущен через `npm run editor`, а не напрямую |
